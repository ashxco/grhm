# CLAUDE.md — GRHM implementation notes

Guidance for agents working in this repository. The product spec is `PRD.md`; the user-facing overview is `README.md`. `AGENTS.md` is this file's mirror for other agents (only the title line differs) — regenerate it whenever this file changes, and do not create additional markdown files.

## What this is

The v0.2 reference implementation of GRHM: a Lisp-shaped programming language for full-stack web applications. The client compiles to React + TypeScript + CSS (history routing, per-page `React.lazy` code splitting, page titles, toasts, dialog focus trap); `(db ...)`/`(api ...)`/`(uploads)` declarations compile to a standalone hardened `node:http` + `node:sqlite` API server (`src/gen/server.ts`, Node builtins only, requires Node >= 22.13) with additive migrations, seeds, indexes, enforced foreign keys (`:references`), input contracts, sessions/auth (`(auth users)`, scrypt + HttpOnly cookies, builtin `/api/auth/*` routes), CSRF (`x-grhm` header), an SSE change feed (`/api/_events`) driving `:live` resources, recurring `(job ...)` tasks, file uploads (`POST /api/uploads` + `/uploads/*` static, paired with the `file-input` element), rate limiting, security headers, JSON logging, `/healthz`, graceful shutdown, and SPA static fallback. It pairs a declarative UI layer with a general-purpose functional core — user-defined pure functions (`fn`, optionally typed params), lambdas, `let`, expression `if`/`cond`/`match` (boolean tests, exhaustive over enums), enums, records (`obj`/`get`), null safety (`or-else`/`is-null`/`not-null`), `attempt`, `fmt`, i18n (`t` + `(i18n ...)` catalogs), recursion, and a list/string/math standard library — shared between client and server via the generated `lib.ts`. Typed rows flow table -> `select` -> api -> resource -> `each`, so dotted field access is checked. Client mutations are `(send method route :prop expr...)` + `(refresh resource)`, both checked against declared api routes and their `(input ...)` contracts (E8xx codes); actions also include `toast` and `try`/`catch`. `src/eval.ts` is a pure-core interpreter behind `grhm eval`/`repl` — its semantics must mirror the compiled output exactly. TypeScript was chosen as the implementation language (PRD open decision 1) for ecosystem alignment.

## Commands

```bash
npm test                 # vitest suite (tests/*.test.ts), 995 tests
npm run test:corpus      # corpus compile/canonical/transcripts + strict TS + React page rendering
npm run test:parity      # interpreter/compiler regressions + seeded generation and shrinking
npm run check            # tsc --noEmit over src + tests
npm run build            # tsc -> dist/ (library + CLI at dist/cli.js)
npm run bench            # PRD 12.1 perf targets against dist/ (build first)
npm run evals            # corpus scorecard (examples/repairs/fix replay/patches) against dist/
npm run test:load        # mixed HTTP/SQLite latency, memory, event-loop budgets
npm run test:browser     # Chromium keyboard, cross-tab auth, and axe audits
npm run test:package     # packed install + scaffold/build/server restart smoke
npm run test:container   # Docker non-root + persistent data + shutdown smoke
npm run site:sync        # build, then regenerate the git-tracked site/dist reference, agent example, examples, and demo bundle
npm run site:check       # site routes/snippets/examples; compares only the op/expression tables and the agent example to the compiler
npm run release:check    # aggregate publish gate (install Chromium first)
node dist/cli.js <cmd>   # run the CLI from the repo
```

The example app: `cd examples/store && npm install && npx grhm build`. Its `grhm` dependency is `file:../..`, so run `npm run build` at the repo root first. `npx grhm test` there runs both lowered suites: Vitest in jsdom (no browser) and Playwright against a real Vite server (requires `npx playwright install chromium` once).

CI is `.github/workflows/ci.yml`: a compiler job on Node 22 and 24 (audits, check, build, test, bench, test:load, evals, site:sync then site:check, test:browser, test:package), an example job (fmt --check, build, full `grhm test` with a real browser), a container job (test:container), and a vscode-extension job (`npm ci` in `editors/vscode`, copies the root README/LICENSE in — gitignored — then `npx @vscode/vsce package` and uploads the `.vsix`). `.github/workflows/release.yml` publishes to npm on `v*` tags (tag must equal `package.json` version; `release:check`, then `npm publish --provenance --access public` with the `NPM_TOKEN` granular automation-token secret). `CHANGELOG.md` (Keep a Changelog) is the third permitted markdown file; `vercel.json` deploys `site/dist` statically with an SPA rewrite.

## Architecture (compile pipeline order)

| Module | Responsibility |
| --- | --- |
| `src/lexer.ts` | Tokens with line/col/file spans; `;` comments; strings; `:keywords` |
| `src/parser.ts` | S-expressions -> canonical AST (`src/ast.ts`), error recovery; a stray `)` (E002) and an unclosed `(` (E003) carry `review` fixes that only the LSP quick fix can apply, since `grhm fix` needs a parsing program |
| `src/ids.ts` | Stable node IDs: hash of parent key + semantic key. Declarations key by name, content nodes by their first string literal, the rest by op + occurrence index; explicit `:id "literal"` wins |
| `src/format.ts` | Canonical idempotent formatter + `projectNames` (compact/descriptive alias rewriting); canonical text is what revisions hash |
| `src/schema.ts` | The op registry: every operation, props, positional shape, motion props, test steps, browser globals, the expression-op contracts (`EXPR_OPS`: arity, `inputs`, `result`, `nullable` for `to-num`/`date-parse`, `throws` for `json-parse`/`chunk`/`regex-*`/`url-decode`/`date-iso`), `ACTION_OPS`, and the `ColumnType`/`PropTypeName` unions shared by analysis, typing, and the fix builders. Checker, codegen, typing, and `reference.ts` all consume it — extend the language here first |
| `src/project.ts` | Multi-file loader: resolves `(include ...)` recursively, detects cycles (E603), assigns IDs globally, merges files into one AST for analysis; `projectRevision` hashes all files |
| `src/analyze.ts` | AST -> `AppModel` (tokens + dark tokens, states, resources with `:poll`/`:live`, pages with `:title`, components, imports, typed fns, tables with `:optional`/`:indexed`/`:references`, seeds, apis with `(input ...)`/`:auth`, enums, envs, auth, jobs, uploads, i18n locales, tests). Tables have their own namespace so a table and the resource reading it can share a name. A post-pass synthesizes the users table and builtin `/api/auth/*` routes for `(auth ...)` |
| `src/typing.ts` | `Scope`/`VarInfo` and recursive `TypeInfo` (nullable values, unions, list elements, optional record fields, row provenance, enums, callable parameters/results), `inferInfo`/`inferType`/`inferCall` (shapes flow through expressions and function/callback calls; scalar result types and nullability come from `EXPR_OPS[op].result`/`.nullable`), null-guard narrowing (`narrowScope` refines identifiers only) and TypeScript type emission, `baseScope`, `fnScope` (pure fn bodies: typed params + fns + imports, no state), `handlerScope` (api handlers: route params + typed `body` + `user` + `env` + fns + imports), `jobScope` (job bodies: fns + imports + `env`, no request context) |
| `src/checked.ts` | Checked server expression metadata: inferred result/bindings and read/write/opaque effects, consumed by typed handler generation and scoped live invalidation |
| `src/runtime/` | Directly tested standalone storage, contracts, quotas/uploads, HTTP/static serving, controls/metrics and database backup/restore modules; build copies their TS sources for generated apps |
| `src/fs-transaction.ts` | Cooperative writer locks, fsynced multi-file journal, rollback and crash recovery for SDK patches, fixes, and formatting; `WriteRefusedError` (a symlinked source file) is the policy refusal the SDK reports as an E503 rejection |
| `src/checker.ts` | Structural/reference/route/resource/type/interop/a11y validation -> structured diagnostics (`src/diagnostics.ts`, codes in `CODE_DOCS`); special forms `if`/`let`/`lambda`/`cond`/`match`/`obj`/`fmt`/`t`, structured argument/storage types, nullable access, and function/callback arity (E112) validated in `checkExpr`; conditions (`if`/`when`/`cond` tests, `and`/`or`/`not` operands) must infer to boolean/unknown/never via `checkCondition` (E111 with `conditionRepair` wrap fixes: safe `(!= x 0)`/`(!= x "")`/`(or-else x false)`/`(not-null x)` for nullable booleans, rows, records, lists, and functions, review `(> (count x) 0)` and `(not-null x)` for nullable scalars/unions/unknown; `checkType` takes a `TypeRepair` provider, default `fallbackRepair` = the or-else wrap); throwing ops (`ExprOpSpec.throws`): literal operands are verified with the runtime's own builtins -> E109 (a literal regex flags operand on its own, whatever the pattern; verdicts memoised per node in `Ctx.literalVerdicts`, so call-site specialisation never re-parses a literal), dynamic ones -> W801 + placeholder `(attempt … fallback)` fix, suppressed by `Ctx.inFn`/`Ctx.inAttempt`, in job bodies as in handlers; `throwingFunctions` marks the fns whose bodies (transitively, by name) hold an unguarded dynamic throwing op and `checkInvocation` warns W801 at their calls outside attempt/fn/test, wrapping the call form; every diagnostic with a mechanical repair carries `fixes` built through `src/fix-builders.ts` (E105 sites share `danglingKeywordDiag`); spelling candidates are the names valid in the position (no bare enum as a value, element ops only in element position, `ACTION_OPS` in action position, table columns in `:where`), a dotted path with an empty segment is a fix-less E201 (`malformedReference`), `set` re-spells only the head and a field path on a known state is E202, and slots that take a reference or an action form carry no placeholder; row-field and enum-member access checked (E812); server ops gated on `Ctx.inHandler` (E801-E819 for db/api/send/refresh/input/auth/i18n/match/live/jobs/uploads/references); send bodies validated against input contracts (E809); job bodies checked in `jobScope` with `inHandler`; seeds, `:references` targets, `:live`-requires-server, and locale consistency validated in `check` |
| `src/check-tests.ts` | Validates `(tests ...)` step shapes, routes, node references: an unknown step is E701 and an unmatched route E203, both with `spellingFix` repairs (step names from `TEST_STEPS`, static page routes); `checkPureExpr` restricts `expect-eq` to literals + stdlib + fns |
| `src/fix-builders.ts` | Pure builders for diagnostic `fixes` (imports only ast/diagnostics/schema/util plus a type-only `ValueType`): `editAt` (the only offset-producing primitive; offsets come from spans, never source text), `makeFix` (validates, sorts, stamps the content id), `replaceSpan`/`renameHeadFix`/`replaceIdentSegment` (no fix for an empty segment)/`keywordFix`/`tokenFix`/`literalFix`/`wrapFix`/`insertAfterFix`/`insertPropFix`/`insertChildFix`/`appendChildFix`, `placeholderLiteral`, `NO_SPELLING`, and `spellingFix` (one `nearestAll` call yields both `suggestions` and `fixes`: a unique hit is `safe` when `isSafeSpelling` holds — names of 4+ characters within distance 2, 3-character names within distance 1, shorter names never — else `review`; ties are `review`, a distance-0 self-hit is nothing). `fixId` hashes title, confidence, and the edits' offsets and text but not the file, so single-source `compile()` ids match the project loader's. Never throws; `undefined` means no fix, so checker sites pass atoms (`parts.op`, a template string) and never compute offsets or fall back to a wider span |
| `src/codegen/` | `css.ts` (static CSS + motion keyframes + dark-token media block + toast/skeleton/dialog/input-error styles), `expr.ts` (expressions/actions/JS imports; lowers stdlib ops, lambdas, `let` IIFEs, `if`/`cond`/`match` ternary chains, `obj`/`get`/`or-else`/`attempt`/`fmt`/`t`, `and`/`or` to `!!(a && b)`/`!!(a || b)` so TypeScript narrows through null guards, enum member reads to string literals, `select :where` to SQL via `genWhere`, db ops to `dbSelect`/`dbInsert`/`dbUpdate`/`dbDelete`/`apiFail`/`dbTx`, `send`/`refresh`/`toast`/`try` actions with async handlers), `tsx.ts` (JSX incl. form/dialog/tabs/menu/table/skeleton/file-input; links pushState-navigate; inputs emit constraint-validation attrs + error line; dialogs wrap in `DialogShell`; file-input lowers to `uploadFile(...).then(setter)`), `runtime.ts` (embedded runtime: per-URL resource cache with shared fastest-consumer polling, AbortController plus generation checks, 30-second retention/128-unused-entry cap, `refreshResource`, and shared-`EventSource` live subscriptions, CSRF `send`, `uploadFile`, history routing, toasts, `DialogShell` focus trap, plus `HELPERS_SOURCE` for the React-free `helpers.ts` shared with the server — including `matchRoute`/`safeDecode`, used by both the client router and the server's request dispatch so route matching cannot drift, and `toNum`/`dateParse`, which turn NaN into null for the nullable parsing ops), `server.ts` (generates the standalone `node:http`+`node:sqlite` server: `SCHEMA` table specs + transactional storage module migrations + indexes + `REFERENCES` clauses, `SEEDS` with one-time seed ledger, sessions + `authRoute` builtins, `validateInput`, SSE `/api/_events` + `broadcastChange` on every db mutation, `JOBS`/`startJobs` intervals, `UPLOADS` + standalone upload store, security headers/CORS/rate limit/body cap/logging/healthz/graceful shutdown, sanitized unexpected API errors with structured diagnostics, SPA static fallback, `handleApi`/`resetDb` exports, test reset hook and rate-limit bypass behind `GRHM_TEST_HOOKS=1`, ignored under `NODE_ENV=production` with one `config-warning` log line), `index.ts` (per-page modules lazy-loaded from `App.tsx`, `lib.ts` for user fns — imports `./helpers.ts` with extension since Node executes it, `i18n.ts` catalogs, page-title effects, sourcemap, `compileNodes()`/`compile()`) |
| `src/patch.ts` | Atomic revision-checked patches (`set/delete/append/insert-before/insert-after/replace/move`); `applyPatchToProject` edits across included files |
| `src/fix.ts` | `applyFixesToProject`: pure multi-pass applier for diagnostic `fixes` (load -> diagnose -> one candidate per diagnostic at or below the requested `level`, explicit ids win, ties skipped `ambiguous`, one confidence tier per pass -> greedy non-conflicting batch, conflicts deferred to the next pass -> apply as text edits -> reload). A batch is kept only if the program still parses and every fixed diagnostic is gone from its site (`code\|file\|message` at the offset the batch's edits moved it to via `mapOffset`, so a fix that unmasks the same message elsewhere still counts; span-less diagnostics fall back to the fingerprint count); otherwise fixes are retried one at a time and the failures blocked by offset-free shape (`ineffective`, `broke-parse`; `invalid-edit` guards malformed edits — no checker fix reaches these verdicts, which `tests/fixes.test.ts` sweeps). Candidates are keyed by fix id plus edited files (identical edits in two files share an id). An explicit id applies once, at the first site offering it in (file load order, offset), and is exempt from the `codes` filter; a requested fix deferred behind a conflicting claim is re-found next pass by shape. `maxPasses` defaults to 8 and clamps to 1..32; `AppliedFix.pass` indexes the counted `passes`; `stopped` is `max-passes` only when eligible fixes remained. E503 on unparsable input, E504 on a stale `revision` or a requested id that no diagnostic offers; changed files are re-canonicalized only when they were canonical before (`format: false` keeps them minimally edited); `uncovered` lists errors that fixing revealed |

| `src/testgen.ts` | Lowers `(tests ...)` twice: Playwright spec (`data-g` locators, exact `getByRole` labels, history-route `goto`) and Vitest jsdom spec (renders real `<App/>`, pushState navigation, `fetch` stubbed to serve `public/`; full-stack apps spawn the generated server as a subprocess on an ephemeral port and forward `/api`, resetting db + resource cache per test). ## Invariants to preserve

- `format(parse(format(x))) === format(parse(x))` (idempotence) and parse -> format -> parse structural equality. Tests enforce both. Projections (`--compact`/`--descriptive`) must not change ASTs or IDs.
- Node IDs must survive formatting and unrelated edits. Never derive IDs from spans or absolute positions. IDs are assigned once per project (after all includes load), not per file.
- Revision = hash over the canonical formatted source of every project file; formatting must not change a program's revision.
- `compile()` emits no files when diagnostics contain errors.
- Generated output must pass `tsc --strict` — `tests/codegen.test.ts` and `tests/corpus-output.test.ts` run tsc over real output, including every corpus app and its actual interop dependencies; keep both green. The corpus gate also renders every generated page with React.
- Patches are atomic: validate the whole patched project (reload with overlaid sources + analyze + check) before returning `ok`.
- Diagnostics are data first: stable `code`, `nodeId`, `span` (with `file` in multi-file projects), `op`, `field`, `received`, `expected`, `suggestions` (display-only hints, never spliced into source), `fixes` (data too: machine-applicable `TextEdit`s in Span coordinates — UTF-16 offsets into the file's current text, `end` exclusive — with a `safe`/`review`/`placeholder` confidence, built only through `src/fix-builders.ts` so offsets never come from source text; `spellingFix` derives suggestions and fixes from one `nearestAll` call so they cannot drift). Human text is a projection (`formatHuman`).
- The checker never executes user code. Interop calls are reference-checked only; `W601` marks them as validated by tsc at build time. Verifying the literal operands of throwing ops with the runtime's own builtins (`JSON.parse`, `new RegExp`, `decodeURIComponent`, `toISOString`) validates a literal, not user code.
- `reference.ts` is generated from the schema — never hand-write op documentation that can drift.
- Corpus examples must compile with zero errors AND be canonically formatted; repair/patch transcripts are replayed by tests. A repair declaring `"fix": "safe" | "review"` must replay through `applyFixes` at that level to the canonical `fixed` text, and an undeclared repair's documented code must survive bulk fixing at level `safe` (the test tells you to declare it). Every diagnostic code a single-file `compile()` can emit has a repair (`tests/corpus.test.ts` enforces coverage; the exemptions live in `UNREPRODUCIBLE_CODES` there), and a code whose transcript exposes a safe fix has a transcript declared `safe` (`tests/fixes.test.ts`). When the language changes, update the corpus in the same commit.
- The fix applier never writes and never trusts an edit it did not re-verify: every pass reloads the edited text and a fix is kept only if its diagnostic (`code|file|message`) is gone from the site the edits moved it to. Fix ids are offset-bound (they hash the edits' offsets and text, not the file), so they are valid only against the text the diagnostics were computed on; results report fresh `diagnostics` for the next request. An explicit id applies exactly once.
- Motion (enter/stagger/hover) always sits behind `prefers-reduced-motion: no-preference`.

## Adding a language feature (checklist)

1. Add/extend the `OpSchema` in `src/schema.ts` (name, aliases, props, positional, children kind, doc — the doc string feeds `grhm reference` and LSP hover); an expression op gets an `ExprOpSpec` with its `inputs`/`result` contract and `nullable`/`throws` flags when they apply.
2. Handle validation in `src/checker.ts` (`checkElement` switch or `checkProps`); new diagnostic codes go in `CODE_DOCS`. Give every diagnostic with a mechanical repair a `Fix` through `src/fix-builders.ts` (`safe` = behaviour-preserving or unique spelling, `review` = intent-dependent, `placeholder` = stand-in value) and a `corpus/repairs.json` transcript declaring its replay level (`"fix": "safe" | "review"`) or leaving it undeclared when only a placeholder exists.
3. Lower it in `src/codegen/tsx.ts` (and `css.ts` if it has structural styles).
4. Add checker tests + codegen assertions (`tests/features.test.ts` for feature-level, `tests/codegen.test.ts` if output structure changes); when the diagnostic carries a fix, add a program to `SITE_PROGRAMS` in `tests/fixes.test.ts` — that sweep is what proves every fix validates, every safe fix clears its diagnostic, and bulk fixing never rejects one; update `tests/fixtures/store.grhm` and `examples/store` if it should be exercised end-to-end.
5. Add or update a `corpus/examples/` program (canonically formatted) and, if the feature has a new diagnostic, a `corpus/repairs.json` transcript — the coverage test in `tests/corpus.test.ts` fails without one. Run `npm run site:sync` when the schema or `CODE_DOCS` changed.
6. Update README's language table.

## Known limitations (v0.2)

- The generated server needs Node >= 22.13 (`node:sqlite`); Node < 22.18 runs it via `--experimental-strip-types` (the CLI and generated configs pick the right invocation from `process.features.typescript`). Server-reachable generated modules (`server.ts`, `lib.ts`) import with explicit `.ts` extensions, which requires `allowImportingTsExtensions` in app tsconfigs (scaffold includes it).
- `select :where` compiles column refs + comparison/logic ops to parameterized SQL. Equality uses null-safe `IS`/`IS NOT` and retains SQLite column affinity (including numeric route IDs). `contains` uses case-sensitive literal `instr`, JavaScript needle coercion, and false for null haystacks; nullable ordering still uses SQL three-valued logic. There are no joins or aggregations at the SQL level (compose in handler expressions via the stdlib). Migrations apply atomically with checksummed numbered SQL files and schema drift detection. Additive changes are automatic; type changes, drops, removed indexes and required-reference backfills need versioned SQL. Seeds apply once; reset is explicit. Backup/verify/restore use the standalone db-admin module. update/delete are `:id`-keyed only. `:references` emits `REFERENCES "t"("id")` DDL but SQLite FK enforcement is on and final migration integrity is checked; there is no cascade support.
- The `:live` SSE feed coalesces committed changes and identifies affected GET routes using checked table-read dependencies (opaque interop conservatively depends on every table). Clients complete in-flight fetches and issue one trailing refresh. Auth apps require a session for SSE. Jobs remain single-process periodic tasks without durable retries; timers handle long intervals and shutdown waits for active jobs. Uploads use local storage with ownership and aggregate/per-user quotas; no object-store backend.
- `(screenshot ...)` lowers to Playwright `toHaveScreenshot`; the first run needs `--update-snapshots` to record baselines (jsdom skips the step).
- Auth is intentionally simple: email + password sessions in SQLite with scrypt hashing, one `(auth users)` per app, no built-in roles, email verification, or recovery. The optional `:provider "./identity.ts"` adapter supports externally verified identities; the provider owns account lifecycle. Password mode has hashing concurrency/account throttles, hashed session tokens, ten sessions per user and logout-all.
- i18n uses the `locale` state and `{param}` templates; there is no pluralization, number/date locale formatting beyond `date-str`, or lazy catalog loading (all locales ship in one module).
- Interop is reference-checked, not type-checked, at GRHM level (`W601`); tsc validates signatures at build time. No `.d.ts` introspection.
- Expression inference tracks nullable values, union branches, list elements, optional record fields, rows, and callable signatures/results, with null-guard narrowing. Opaque interop and external resource payloads remain unknown; null-initialized mutable state has an unknown payload, and recursive calls without concrete return evidence fall back to unknown. Source parameter annotations cover base types and table names; there is no generic or explicit union annotation syntax. Conditions are checked for boolean type, but `narrowScope` only refines identifiers, so `(cond ((is-null (first xs)) …) ((> (first xs) 0) …))` still needs a `let`; `select :where` predicates go through `checkWhere`, which has no boolean-condition rule.
- `grhm fix` is a text-edit applier, not a refactoring engine: it applies the fixes diagnostics already carry, one confidence tier per pass, at most 8 passes by default (32 max), and re-verifies by reloading; it never invents an edit, and fix ids are offset-bound so a stale id is an E504. It requires a parsing program (E503 otherwise), so the parser's own `review` fixes for a stray `)` (E002) or a missing `)` (E003) are applied by hand or through the LSP quick fix, never in bulk. W801 is a heuristic: any non-literal deciding operand of a throwing op counts as dynamic (no data-flow analysis), a fn whose body has one warns at every call (arguments are not inlined, so literal arguments warn too; fn references are matched by name, so a local shadowing a fn name counts), and the only fix it offers is a placeholder `(attempt …)` that bulk fixing never applies.
- `grhm test` steps are a fixed vocabulary (`visit/click/fill/press/expect-text/expect-gone/expect-node/expect-count/expect-value/expect-url/expect-eq/screenshot`); `expect-eq` covers pure expressions only — no assertions on live state or network traffic.
- `grhm eval`/`repl` cover the pure core only (by design); state, resources, interop, and server ops require a compiled app.
- LSP completion is schema-driven (ops + props), not position-type-aware; code actions are exactly the diagnostic `fixes` (no refactorings). Rename covers states/resources/components/tokens/locals/each vars; imports and component props are deliberately not renameable (an import name doubles as the JS export name; prop call sites are keywords).
- Motion `:stagger` emits nth-child delays for the first 12 children; later children animate without extra delay.
- Occurrence-indexed IDs (nodes with no name and no string literal) still shift when a same-op sibling is inserted before them; explicit `:id` is the mitigation for patch-heavy flows (the corpus patch transcripts model this).
- The VS Code extension is a standard `vscode-languageclient` wrapper but has not been launch-tested in an actual VS Code instance.
- Versions in `src/scaffold.ts` templates are pinned to what this repo has installed; keep them in sync with root `package.json`.

- Strict TS, `noUncheckedIndexedAccess`; ESM with `.js` import suffixes (NodeNext).
- Exhaustive switches over unions end with a `never` check.
- Imports at top of file; no inline imports.
